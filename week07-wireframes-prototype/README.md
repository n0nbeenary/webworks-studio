## 5. Prototype Flow
Describe the user task your prototype demonstrates.

**Starting point:**  The starting point is a Trails page that prompts the user to select filters per their hike requirements. All trail cards will display at this point.
**User action:**  Maya will select the filters applicable to her search and then hit the submit button.
**System/interface response:**  The interface will filter the results so they match the selected filters.
**End state:**  Only the trail cards for traisl that match the selected filters will display.

---

## 6. Design Rationale
Document approximately three important decisions.

### Decision 1
**Problem:**  Maya could not easily compare key trail information when looking at the trail cards.
**Design response:**  I added key trail information to the template for the trail cards.
**Why:**  The ability to quickly compare choices on a phone was one of Maya's core questions so the information should be available and easy to process.

### Decision 2
**Problem:**  Maya could not filter trails to match her needs.
**Design response:**  Added a working filter with multiple options at once.
**Why:**  This will greatly decrease the time needed to compare trail options.

### Decision 3
**Problem:**  Buttons were not uniform and would cause confusion about what parts of the interface are interactive.
**Design response:**  I chose one standard button for throughout the interface.
**Why:**  Having clear CTAs will guide Maya to successfully navigate the website without bouncing.
